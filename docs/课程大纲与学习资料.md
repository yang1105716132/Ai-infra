# AI Infra、GPU 硬件与 Stanford CS336 综合学习项目

**版本：CS336 融合版｜36 周｜建议每周 10–12 小时**

这是一条从语言模型底层实现到 GPU 集群系统的完整路线。Stanford CS336 负责补足「语言模型怎样从数据走到训练、评测和 post-training」；GPU/AI Infra 主线则进一步展开芯片、内存、互连、性能分析、调度、监控和容量成本。最终交付一个可复现的小型语言模型训练与推理系统。

CS336 2026 官方课程将主题组织为分词与模型基础、PyTorch 资源核算、架构与 MoE、GPU/Triton、并行、scaling laws、推理、评测、数据、SFT/RLHF、RLVR 和多模态；对应五项作业分别是 Basics、Systems、Scaling、Data、Alignment and Reasoning RL。[官方课程与作业说明](https://cs336.stanford.edu/) [官方讲义仓库](https://github.com/stanford-cs336/lectures)

---

## 学习目标与结业作品

完成项目后，应能：

1. 从原始文本构建语料、tokenizer 和 Transformer 语言模型，训练一个小型模型并解释训练曲线。
2. 估算模型参数、激活、优化器状态、KV cache 的显存需求，以及训练/推理的算力和数据带宽需求。
3. 用 CUDA 或 Triton 写出基础 GPU kernel，使用 profiler 和 Roofline 证据解释瓶颈。
4. 设计并评测 DDP、FSDP、张量并行、流水线并行等训练策略，解释通信代价和扩展效率。
5. 构建可复现的 GPU 环境与推理服务，测量吞吐、延迟、并发、利用率和单位成本。
6. 解释数据质量、模型评测、SFT/RLHF/RLVR 对模型行为的影响。

**结业作品**：训练并部署一个小型 Transformer LM，配一份数据治理记录、训练与 GPU 性能报告、在线服务基准、硬件拓扑/容量成本模型和复现说明。

建议模型大小按设备调整，通常从 **10M–100M 参数**级别起步；数据只取具有合适使用条件的小型公开样本或 Common Crawl 子集。课程重点是系统性测量与可复现，不追求参数规模。

## 前置要求与补课路径

CS336 官方要求较强的 Python、PyTorch、深度学习、系统优化、内存层次、线性代数、微积分、概率统计和机器学习基础；课程本身实现量很大。[CS336 先修要求](https://cs336.stanford.edu/)

如果下面任一项不熟，建议先补 2–6 周，再开始主线：

- Python、Git、Linux shell、基础软件工程：能读写模块化 Python、运行命令行程序、管理依赖和调试异常。
- PyTorch：熟悉 Tensor、自动求导、nn.Module、优化器、DataLoader 和 GPU 张量。
- 数学：矩阵乘法、softmax、交叉熵、梯度下降、概率分布与均值/方差。
- 系统基础：进程、内存层次、缓存、带宽/延迟、并行和网络基础。

补课资料： [PyTorch Learn the Basics](https://docs.pytorch.org/tutorials/beginner/basics/intro.html)、[CUDA Programming Guide 的基础章节](https://docs.nvidia.com/cuda/cuda-programming-guide/)、[PyTorch CUDA semantics](https://docs.pytorch.org/docs/stable/notes/cuda.html)。

## 时间安排

每周 10–12 小时：2 小时听课/读讲义，5–7 小时做代码与实验，2 小时写实验记录和复盘。若每周只有 6–8 小时，可把 36 周拉长到约 48 周。

- 没有 GPU：先在 CPU 上实现和验证小规模功能；在 GPU 到手后补 kernel、性能和服务测量。GPU 内核部分可以先读代码与做 Roofline 估算，不能把估算结果冒充实测。
- 只有单卡：完成大多数课程和 capstone；多卡扩展部分用较小模型实测单机可用卡数，其他配置做明确标注的容量与拓扑分析。
- 使用云端算力：先在 CPU 上验证正确性，再启动短时 GPU 实验；记录 GPU、驱动、库版本、时长和费用，并在实验后关闭实例。CS336 官方也建议先用 CPU 调试，再用 GPU 完成训练和 benchmark；具体服务价格会变化，使用前查看服务方当前报价。[官方 GPU compute 建议](https://cs336.stanford.edu/)

## 逐周学习主题、资料与实践

### 第 1 周｜语言模型全流程与 Tokenization

- **CS336 YouTube**：[Lecture 1：Overview, Tokenization](https://www.youtube.com/watch?v=JuoVZkPBiKk)

- **核心内容**：从文本到 token id，再到 next-token prediction；tokenizer 的词表、压缩率、编码/解码和序列长度成本。
- **CS336 资料**：[Lecture 1：Overview, Tokenization](https://github.com/stanford-cs336/lectures/blob/main/lecture_01.py)、[A1 Basics](https://github.com/stanford-cs336/assignment1-basics)。
- **实践与交付**：用小型中英文文本实现或分析 BPE tokenizer；测不同 tokenizer 的词表大小、每段文本 token 数、encode/decode 可逆性；记录 tokenizer 对模型上下文长度和训练成本的影响。

### 第 2 周｜PyTorch、Einops 与资源核算

- **CS336 YouTube**：[Lecture 2：PyTorch, resource accounting](https://www.youtube.com/watch?v=kuYAsz7zspQ)

- **核心内容**：张量维度、模型模块、训练 step；参数量、FLOPs、激活、权重、梯度、优化器状态和算术强度的估算。
- **CS336 资料**：[Lecture 2：PyTorch、einops、resource accounting](https://github.com/stanford-cs336/lectures/blob/main/lecture_02.py)、[A1 Basics](https://github.com/stanford-cs336/assignment1-basics)。
- **补充**：[PyTorch CUDA semantics](https://docs.pytorch.org/docs/stable/notes/cuda.html)、[PyTorch Benchmark recipe](https://docs.pytorch.org/tutorials/recipes/recipes/benchmark.html)。
- **实践与交付**：为 10M、100M 参数模型各做一份训练内存估算；用 CUDA events 或 benchmark 工具测一个算子；分开记录 kernel、数据传输和端到端时间。

### 第 3 周｜Transformer 架构与超参数

- **CS336 YouTube**：[Lecture 3：Architectures, hyperparameters](https://www.youtube.com/watch?v=lVynu4bo1rY)

- **核心内容**：Embedding、位置编码、attention、MLP、normalization、residual、初始化、上下文长度、层数/宽度等设计选择。
- **CS336 资料**：[Lecture 3：Architectures, hyperparameters](https://github.com/stanford-cs336/lectures/blob/main/lecture_03.pdf)、[A1 Basics](https://github.com/stanford-cs336/assignment1-basics)。
- **补充论文**：[Attention Is All You Need](https://arxiv.org/abs/1706.03762)。
- **实践与交付**：画一个 decoder-only Transformer 的张量形状流；实现 attention/MLP/Transformer block；加入 shape、mask 和数值稳定性检查。

### 第 4 周｜Attention 替代方案与 Mixture of Experts

- **CS336 YouTube**：[Lecture 4：Attention alternatives and MoE](https://www.youtube.com/watch?v=cKSwj_qZ8Jg)

- **核心内容**：dense attention 和高效 attention 的动机；MoE 的 router、expert、稀疏激活、负载均衡和通信开销；总参数与 activated parameters 的区别。
- **CS336 资料**：[Lecture 4：Attention alternatives and Mixture of Experts](https://github.com/stanford-cs336/lectures/blob/main/lecture_04.pdf)。
- **补充论文**：[Switch Transformers](https://arxiv.org/abs/2101.03961)。
- **实践与交付**：对 dense FFN 与 toy MoE 比较参数、激活参数、FLOPs、内存及潜在 all-to-all 通信；写出在哪种 workload 下 MoE 可能不划算。

### 第 5 周｜GPU、TPU 与加速器架构入门

- **CS336 YouTube**：[Lecture 5：GPUs, TPUs](https://www.youtube.com/watch?v=izZba4UA7iY)

- **核心内容**：数据中心加速器与 CPU 的角色；SIMT/SIMD 思路、矩阵运算单元、HBM、板卡功耗和跨设备互连。
- **CS336 资料**：[Lecture 5：GPUs, TPUs](https://github.com/stanford-cs336/lectures/blob/main/lecture_05.pdf)。
- **补充资料**：[NVIDIA H100 Architecture 白皮书](https://resources.nvidia.com/en-us-hopper-architecture)、[AMD MI300X 规格](https://www.amd.com/en/products/accelerators/instinct/mi300/mi300x.html)、[AMD GPU architecture 文档](https://rocm.docs.amd.com/en/develop/reference/gpu-arch/index.html)。
- **实践与交付**：制作至少两款 NVIDIA/AMD 加速器对照卡，字段包含显存、带宽、数据类型、功耗、互连、软件栈和来源日期；分开标注厂商峰值与实测结果。

### 第 6 周｜GPU Kernels 与 Triton

- **CS336 YouTube**：[Lecture 6：Kernels, Triton](https://www.youtube.com/watch?v=xnDHaNUvHBg)

- **核心内容**：kernel launch、thread/block/program、索引、mask、内存读写、同步与 host-device 边界。
- **CS336 资料**：[Lecture 6：Kernels, Triton](https://github.com/stanford-cs336/lectures/blob/main/lecture_06.py)、[A2 Systems](https://github.com/stanford-cs336/assignment2-systems)。
- **补充资料**：[Triton Tutorials](https://triton-lang.org/main/getting-started/tutorials/)、[CUDA Programming Guide 基础](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/intro-to-cuda-cpp.html)。
- **实践与交付**：实现向量加法、reduction 或简易 matmul；测试非整除 block、空输入和不同尺寸；对照 PyTorch 结果和误差。

### 第 7 周｜并行训练 I：数据并行与 Collective

- **CS336 YouTube**：[Lecture 7：Parallelism](https://www.youtube.com/watch?v=SzpOcwdIL0Y)

- **CS336 资料**：[Lecture 7：Parallelism](https://github.com/stanford-cs336/lectures/blob/main/lecture_07.py)、[A2 Systems](https://github.com/stanford-cs336/assignment2-systems)。

## 五项作业如何融入本项目

| CS336 作业 | 对应周 | 自学版成果 |
|---|---:|---|
| A1 Basics | 1–3、30–31 | tokenizer、模型架构、optimizer 和小规模 LM |

| A3 Scaling | 9、11、28、31 | scaling-law 拟合、算力预算和小模型规模实验 |
| A4 Data | 13–15、30 | 小型网页语料处理、过滤、去重、混合和数据流水线 |

**资源缩放原则**：先做正确性，再做性能；先用小数据和小模型，再扩规模。部分 CS336 作业的原始规模对个人设备很重，自学时缩小规模，但保留测量方法和分析问题。

| 项目 | 分值 | 通过标准 |
|---|---:|---|
